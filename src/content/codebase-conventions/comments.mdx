Agents often add a paragraph to explain a simple check.

```ts
// Validate the email address before submitting the form.
// If the address is invalid, show a validation error to the user
// and return early to prevent the form from being submitted.
if (!isValidEmail(email)) {
  setError('Enter a valid email address.');
  return;
}
```

## Why it hurts

- **Tokens.** Every comment is read again each time an agent loads the file.
- **Justification.** A comment explaining a bad pattern makes it look intended, and the agent copies it elsewhere.
- **Staleness.** Code changes, comments don't. The next agent trusts the comment over the code.
- **Noise.** The one comment that matters gets buried.

## AGENTS.md

```md
- No comments unless necessary. Make the code clearer instead.
```

## What stays

A reason the code can't express, like a workaround or a platform quirk:

```ts
// The backend returns 200 with an empty body on expired sessions instead of 401.
if (response.ok && !(await response.text())) {
  return redirectToLogin();
}
```

## What goes

Anything the code already says. Fix the code instead:

```ts
// Before
// Start each topic animation 50 ms after the previous one.
// Add 1 to the zero-based index so the first topic also has a delay.
const delay = 0.05 * (topicIndex + 1);

// After
const delay = firstSectionDelaySeconds + sectionStaggerSeconds * topicIndex;
```

## Existing code

Ask the agent to apply the rule to the codebase. It removes every comment that doesn't carry a reason.
